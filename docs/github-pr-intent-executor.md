# Ejecutores GitHub PR y aprobación: fixture in-memory (#762)
## Alcance y autoridad
Autorización específica del dueño en la puerta [#879](https://github.com/pl0n3r/ControlBot/issues/879): `/decidir A` con journal `factory-human-decision` v2. La autorización alcanza **solamente simulaciones offline** de `pr.review`, `pr.merge` y `release.approve` con transporte **fake**, sin API GitHub, tokens, licencias, permisos runtime, releases, deploy ni efectos productivos. `GitHubIntentPolicy` y `CapabilityPolicy` siguen imponiendo `DENY` en ejecución real. La prueba exige fixture firmado y verificado de `GitHubIntentTestGrantAuthority` y no acepta un simple campo `authorized=true` proporcionado por un caller.
`src/GitHubPullRequestIntentExecutor.php` expone únicamente el método puro `simulate()`: recibe un envelope de intención validado y cinco fuentes de prueba explícitas (`fixture`, estado, auditoría y ledger). No recibe URL, HTTP client ni credenciales productivas; no importa SDK y nunca realiza I/O. El transporte fake se representa como un resultado tipado (`success|failure|ambiguous`), no como una operación remota. Incluso cuando reporta `fake_effect.status=simulated`, el recibo **siempre** declara `decision=deny`, `execution=false` y `runtime_authorized=false`.
## Contratos y seguridad
- Una simulación PR exige número positivo, HEAD de 40 caracteres hexadecimales, estado mergeable y evidencia explícita de checks. `pr.merge` requiere `expected_head_sha` idéntico, `mergeable=true` y todos los checks terminales en verde, incluyendo los mínimos `Validar`, SonarCloud, CodeQL y Factory policy. Un check ausente, pending, skipped, failed o duplicado bloquea el efecto fake.
- La autoridad sintética pasa por los contratos existentes `GitHubIntentEnvelope`, `GitHubIntentAuthorityRequirements` y `GitHubIntentTestGrantAuthority`: titular, scope, nonce, expiración, revocación, firma y servidor. No se convierte una prueba HMAC en una concesión runtime.
- `release.approve` comprueba `candidate_sha` y `release_ref` explícitos. Solo agrega al estado fake una aprobación con `published=false`; no configura bootstrap, canal `Factory@v1`, release o deploy.
- Se aplican límites de filas, rechazo de campos adicionales, códigos de motivo fijos y ledger idempotente. Repetir la misma intención y fixture conserva el resultado previo sin segundo efecto. Reutilizar una clave con distinto fingerprint devuelve `idempotency_conflict`. Los resultados y auditoría no contienen claves HMAC, pruebas de firma, tokens ni identidades de proveedores.
- Los fallos o resultados ambiguos conservan intacto el estado de entrada. La prueba de regresión opera con `php` y fixtures sintetizados; ni las pruebas ni el CLI pueden ejecutar `github.pr.merge` real.
